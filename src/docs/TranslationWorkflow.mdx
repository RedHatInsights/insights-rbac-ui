# Translation Workflow

RBAC UI keeps FormatJS message definitions in `src/Messages.js` and generated catalogs in `locales/` and `src/locales/`. Do not edit generated catalogs by hand.

## Author messages

Add messages to `src/Messages.js` with a stable `id`, English `defaultMessage`, and translator-facing `description`. Check `locales/translation-template.json` for existing IDs before adding a descriptor.

## Generate catalogs

After changing messages, run:

```bash
npm run translations
```

The command extracts `src/Messages.js` into `locales/translation-template.json`, compiles English runtime messages into `src/locales/translations.json`, and generates `src/locales/data.json`. Review and commit all generated files with the source change.

`npm start`, `npm run start:no-proxy`, and `npm run build` run `translations:prepare` first. It compiles the checked-in source catalog and rebuilds the runtime aggregate.

| Path                                | Role                                      |
| ----------------------------------- | ----------------------------------------- |
| `locales/translation-template.json` | Generated English descriptors and context |
| `src/locales/translations.json`     | Compiled English runtime messages          |
| `src/locales/data.json`             | Runtime aggregate keyed by locale          |

## Runtime locale support

`src/locales/locale.ts` currently selects `en` unconditionally. Runtime locale selection remains a separate product change.
